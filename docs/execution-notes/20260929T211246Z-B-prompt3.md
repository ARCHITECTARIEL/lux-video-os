## Implementation

All three production `finalizeReadyJob` callers (Premium, Standard simulation, Standard RunPod) now pass through a mandatory stored-media validation boundary in the repository. All five final writers use the immutable private-storage gateway.

1. **Real validation:** bundled `ffmpeg-static`, without adding ffprobe or another dependency. Force MOV/MP4 demuxing and file/pipe protocols; fully decode audio and video separately. Require exactly one video/audio stream, decoded frames, valid duration, matching A/V duration, exact format dimensions and bounded bytes. Child process timeout and diagnostics are bounded and errors sanitized.
2. **Stored identity:** read actual private object bytes, compare exact count/SHA-256 and canonical account/job/hash path, then decode a unique local copy. Incoming acceptance metadata is overwritten by the validator. Standard expected duration comes from the owned narration asset; Premium expected duration comes from decoding the downloaded provider source.
3. **Atomic completion:** after validation, lock/re-read the job; verify identity/input/format/status and acceptance. Check existing final/media/ledger identity, settle once, persist media dimensions/duration, accepted output and one completion event in one transaction. Same accepted artifact replays without debit/event; differing or legacy-unaccepted ready artifacts reject. Generic `transitionJob(...ready)` is blocked; standalone credit finalization is readback-only.
4. **Immutable final storage:** force no-overwrite regardless of caller options, verify bytes against content-addressed path, and permit reuse only after actual matching readback. The filesystem driver uses atomic no-replace publication to prevent racing overwrites. A lost write acknowledgement can recover only through verified identical bytes.
5. **Download integrity:** buffer up to 100 MiB and verify bytes/hash before sending any bytes. Replaced/corrupt objects cannot leak a partial response. Reads have a 60-second deadline.
6. **Failure/retry:** deterministic rejection reaches failed/release handling, preserving balance and releasing the reservation. Private rejected objects are retained with a safe hash/size in failure evidence for later quarantine/GC; automatic deletion could race with a successful retry. Each finishing attempt has its own temporary directory and cleans it. Overlapping finishing/containment claims and stale polls do not regress/fail an advanced job. Standard simulation resumes every persisted local stage without repeating a remote submission; unknown/real remote jobs remain held.
7. **Renderer contracts:** Remotion recognizes the actual `vertical` format. HyperFrames scales the existing composition's timing to the decoded source duration instead of truncating it to 5.24 seconds; dimensions/style/template snapshot are unchanged. HyperFrames remains landscape-only. RunPod output that does not meet requested dimensions now fails acceptance rather than being mislabeled successful.

## Concrete policy

- Final size: positive, at most **100 MiB**. Source inspection uses the same bound.
- Duration: positive, at most **180 seconds**.
- A/V duration agreement and source/output tolerance: **max(500 ms, 5%)**.
- Dimensions: landscape **1920x1080**, vertical **1080x1920**, square **1080x1080**.
- Exactly one H.264 video and one AAC audio stream. No silent/missing-stream acceptance.
- Decode timeout: **120 seconds per stream decode**, with bounded diagnostics. Stored read timeout: **60 seconds**.
- Acceptance remains policy `video-os-media-v1`, with actual validator/FFmpeg version and bound artifact/media evidence.

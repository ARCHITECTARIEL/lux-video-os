## Repairs and review decisions

1. Talent discovery now awaits the same persisted Premium permission check as rendering. Configured account/email or an empty allowlist cannot bypass persisted grant/revocation. Anonymous is 401, denied is 403, database/config failure is sanitized 503 before provider discovery.
2. `transitionJob(...provider_submitting)` now checks job binding and persisted tier permission within its existing transaction, holding the entitlement share lock through the submission claim. **The claim is the authorization ordering boundary**: revocation committed before the claim blocks it; a claim already committed may complete its provider request. This does not promise cancellation of already-claimed/in-flight external work. Real PostgreSQL race verification is still outstanding.
3. Premium idempotent replay rejects changed provider/title/format/cost/source input with 409, compares JSON independent of key order, and validates saved server authorization binding. Exact replay returns the existing job without another reservation. Only server-added authorization metadata is excluded from input comparison. Shared stable JSON logic is reused from the Standard implementation.
4. Sign-in/admin identity resolution compares lowercased stored email and fails 409 for multiple matching identities instead of selecting arbitrarily. This is a bounded compatibility repair, not a database-wide case-insensitive uniqueness migration. Current creation paths use normalized email/canonical IDs; concurrent legacy collisions still need real DB verification.
5. Explicit administrator revocation remains authoritative across **all** later sign-in methods, including workspace password. Re-enablement requires a new admin grant. The older unconditional workspace capability statement was incomplete. Do not “repair” this by silently restoring revoked access. A new regression makes this policy explicit.
6. Legacy jobs lacking `renderAuthorization` retain the existing compatibility policy: current persisted permission is required before a new submission claim. Present-but-invalid bindings fail closed. Existing provider IDs recover without resubmission. Inventory/cutoff policy is a future release consideration, not silently changed here.
7. Both workers now distinguish entitlement denial before a successful claim from uncertainty after claiming. The former stays ENTITLEMENT and is released by failure handling; already-claimed/concurrent submissions remain held against duplicate provider calls. Premium and Standard regressions first failed with PROVIDER_SUBMIT_UNKNOWN, then passed after the fix.

The original October 1 evidence and its October 2 15:11:53.953 UTC expiry are unchanged. `config/heygen-space-refresh.json` is deliberately pinned with `observation:null`. Current runtime resolution therefore still fails closed on the expired original anchor.

The new supported transition preserves the original credential/scope/promotion rows and their evidence digests. This is a deliberately review-controlled freshness policy, `reviewed-neutral-asset-reprobe-24h/v1`. It is not automatic renewal. Live qualification still lasts at most 60 seconds. Freshness cannot be installed by environment variables, per-request arguments, bootstrap, a serialized binding, or an unreviewed JSON file.

### Exact next steps for a fresh observation

1. Obtain separate, bounded owner approval for the new neutral probe: the exact canonical HeyGen credential and native space; one upload of the already-pinned 95-byte 32x32 PNG; one metadata read; deletion of only that newly returned asset ID; one absence readback; two qualification GETs; no retries, generation, or unrelated reads/deletes. The prior probe's one-off approval is exhausted. Credentials must use an approved private channel and never enter the repository.
2. Execute that approved probe with correlated private network observations. Qualification must use `qualifyHeygenCredential` from `services/heygen-account-qualification.js`. Preserve its returned qualification object privately as `qualification.json` without an API key. Stop on uncertainty; do not retry an upload or broaden cleanup.
3. Preserve four private receipt objects as `upload.json`, `read.json`, `delete.json`, `readback.json`. Each has exactly `method`, `pathTemplate`, `observedAt` (canonical UTC ISO), `status`, `errorCode`, `data` (provider response's data, or null for absence), `assetIdSha256`, `fixtureSha256`. Use `/v3/assets` for the upload and `/v3/assets/{probe_asset_id}` for the other three templates. The upload is POST; read/readback GET; deletion DELETE. Hash the same returned asset ID in every receipt. Do not include authentication headers, cookies, tokens, full request URLs, or unrelated responses.
4. Keep only these five files in a protected private directory (0700 directory and 0600 files on POSIX). Run `node tools/prepare-heygen-space-refresh.mjs --private-evidence-dir <absolute-private-directory>`. This is an offline validation/preparation tool, not a network collector or authority installer. It checks the full identity, neutral fixture, asset ownership, same asset/space, successful deletion, `404 asset_not_found` readback, monotonic timeline and hashes. Its output is public-safe and explicitly `reviewRequired:true`, `installed:false`, `databaseChanged:false`.
5. Independently review the actual network observations and bounded approval. Matching JSON/hash relationships alone do not authenticate a provider response. Review must establish that the recorded requests/responses were genuinely observed, one asset was used, no unexpected mutation/retry occurred, and cleanup completed. Then review a source change containing the candidate document in `config/heygen-space-refresh.json` and its exact canonical digest in `PINNED_REFRESH_SHA256` in `lib/heygen-space-refresh.js`. Do not copy the wrapper object; use its `candidate`. Keep the raw private receipts outside this public repository.
6. Run focused and aggregate checks and exact-candidate packaging. Runtime staging includes the refresh document byte-for-byte for regular and Workflow functions. Deploy only through the separately authorized release process. Resolve the account against the canonical live database and inspect its redacted status after deployment. There is no DB evidence rewrite or schema migration for this transition.

Requalification by itself is insufficient to prove the credential still maps to the same native provider space. Simply editing the old timestamp/expiry, replacing original DB evidence, or setting `productionReprobePolicy` without a fresh observed chain is not supported.
